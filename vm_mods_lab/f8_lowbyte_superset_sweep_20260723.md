# GB202 `0x8200f8` low-byte superset sweep — 2026-07-23

Scope: isolated VFIO VM only. Host display remained on the AMD iGPU; the RTX
5090 was already passed through to `mods-lab-gpu-primary` via `vfio-pci`.

No VBIOS, firmware, InfoROM, OTP, PCI config, clock, voltage, reset, latch
request, raw L2 mask, effective L2 mask, or software L2 mask write was
performed. The only device register written by the test binary was
`BAR0[0x008200f8]`.

## Tool

Host-built static binary:

```text
8ab181cea88c8f7b13eaa0d87dcc6471a99c2d6822bed541226fe2d6891c399e  gb202_f8_superset_sweep
```

ISO:

```text
d5d57f0261e6e8697a3130291e77aafc43b354efb5fdd9cb1f85bccb8f763533  gb202-f8-sweep.iso
```

The tool requires the known baseline before each write and stops if any tracked
state changes unexpectedly. It only tries low-byte candidates that keep all
currently-set `0x8f` bits and only add bits among `0x10/0x20/0x40`:

```text
0x8f, 0x9f, 0xaf, 0xbf, 0xcf, 0xdf, 0xef, 0xff
```

Full 32-bit values were generated by preserving the current upper 24 bits:

```text
0xfffffb8f
0xfffffb9f
0xfffffbaf
0xfffffbbf
0xfffffbcf
0xfffffbdf
0xfffffbef
0xfffffbff
```

```text

candidate[2] low=0xaf write 0xfffffbaf -> readback 0xfffffb8f

candidate[6] low=0xef write 0xfffffbef -> readback 0xfffffb8f
candidate[7] low=0xff write 0xfffffbff -> readback 0xfffffb8f
```

For every candidate, FSP/MNOC status stayed:

```text
send=0x80000000
recv=0x85000009
```

Final tracked state was identical to the baseline:

```text
final f8 = 0xfffffb8f
final fbp0..7 raw       = 0x00000012
final fbp0..7 effective = 0x00000012
final fbp0..7 software  = 0x00000000
```

Guest `dmesg | tail -80` after the sweep showed ISO mount messages and one
unrelated AppArmor cache warning. It showed no new Xid, PCIe AER, vfio fatal
error, FSP error, GSP error, or guest kernel fault attributable to this sweep.

## Conclusion

The “maybe `0xfffffbff` is just the wrong open value” hypothesis was tested for
the monotonic low-byte superset set. None of the tested values was accepted.

This strengthens the current model:

- `0x8200f8` is not writable from the ordinary host-visible BAR0 path, even when
  trying the plausible low-byte open combinations that do not clear existing
  enabled bits;
- the rejection remains silent at the visible BAR0 and FSP/MNOC status surfaces;
- the 5090 L2 raw/effective mask remains `0x12`, so this route still does not
  expose a usable runtime L2 enable path.
