# 证据分级（E0–E6）

> 本文件定义 `FINDINGS.md`、`CORRECTIONS.md`、`OPEN_QUESTIONS.md`、`NEXT_STEPS.md` 中使用的证据级别。
> 版本：2026-10-18。与 `docs/DEDUP_PLAN.md` §0 的定义一致，本文件是唯一权威版本。

## 1. 为什么要分级

本库的历史文档混用了三类完全不同的执行载体：

- 物理 RTX 5090（宿主直连或直通 VM）；
- 只读反汇编 / 官方源码 / VBIOS 文件；
- QEMU lab 或旧 `rv64_emu.py` 解释器。

三者都能产生“跑通了”的观感，但只有第一类能支撑“真机行为”的结论。历史上已经出现过把 lab 的受控入口写成真机 U-mode 路径的例子（见 `CORRECTIONS.md` C-01）。因此**每条结论必须携带执行载体**，而不是作者自评的“已验证 / 实锤 / A 级”。

## 2. 级别定义

| 级别 | 名称 | 最低证据要求 | 能支撑的结论 | 不能支撑的结论 | 典型来源 |
|---|---|---|---|---|---|
| **E0** | 真机裸机 | 物理卡由宿主内核直接驱动；命令与输出可复现；有 dmesg/寄存器/nvidia-smi 原始记录 | 硬件行为、固件行为、时序、恢复流程 | 芯片内部未观测结构；跨固件版本 | 宿主直跑的 FSP/GSP/时钟实验 |
| **E1** | 真机直通 VM | 物理卡整 IOMMU 组直通；客体内执行；宿主不绑定 nvidia | 同上，但需注明 VM 环境 | 宿主驱动特有路径；裸机时序绝对值 | `vm_mods_lab/*`、K3-1 注入、泄漏读 |
| **E2** | 静态 | 原始固件/官方源码/头文件/VBIOS 的字节级依据；给出 VA 或文件偏移 | 代码路径、字段布局、常量、调用图 | 运行时取值、是否真的执行、硬件语义 | `power_governor_reverse/*`、`fsp_ace_static/*` |
| **E3** | 模拟器（QEMU lab） | `gsp_qemu` 主线；原始镜像 + 可重复的 lab 测试；输出含寄存器/哈希 | 在**该 profile** 下的执行流、表结构、分支语义 | 真机地址布局、真机可达性、认证链完成 | `gsp_qemu/*` |
| **E4** | 旧 Python 模拟器 | `rv64_emu.py` + 真机内核 ELF；脚本与步数可复现 | 指令级语义、算术、控制流 | 真机可达性；已按 `AGENTS.md` 降级为历史参考 | `KERNEL_PRIVESC_C1_C2_PROOF`、`C2_ENTRY_AUDIT` |
| **E5** | 二手综合 | 基于既有文档的复盘、清单、汇辑；给出被引文档 | 索引、时间线、待办、对外记录 | 任何一手事实 | `VULN_INVENTORY`、`RESUME_BRIEF`、`PSIRT_DRAFT_*` |
| **E6** | 公开/第三方 | 可核验的网页、厂商文档、第三方项目 | 公开基线、外部案例、第三方模型 | 本项目硬件行为 | `mclk4000_public_cases/*`、`open-iov-device-model.md` |

### 2.1 组合级别

允许写 `E2/E4`、`E0+E2` 这类组合，含义是“两条独立证据链指向同一结论”，必须同时给出两个来源。例：

- `OBJ-01` TYPECALC 公式 = `E2/E4`：静态反汇编给出指令，旧模拟器逐值复核。
- `CLK-10` XBAR 独立时钟域 = `E0+E2`：真机 A/B 有吞吐变化，静态有独立 PMU 对象/时钟源。

**禁止**用“E3+E0”把模拟器结论和真机结论合并成一条（见 §3 规则 3）。

### 2.2 证据 vs 置信度

- **证据级别**回答“在哪执行/依据是什么”，是客观分类。
- **置信度**回答“这条结论有多稳”，取 `高 / 中 / 低`：
  - 高：多次独立观察，或静态与动态互证，或可重复的确定性测试；
  - 中：单次实验、单一来源、或负结果但排除范围有限；
  - 低：推断、未复现、依赖未验证前提。

一条 E0 结论也可以是低置信度（只跑过一次），一条 E2 结论也可以是高置信度（指令直接可见）。两者不可互相替代。

## 3. 裁决规则（与任务约定一致）

1. **后续文档明确覆盖且带证据 → 以后续为准**，写入 `CORRECTIONS.md`，并在 `FINDINGS.md` 保留被更正条目的历史 ID。
2. **后续只是声称、没有证据 → unresolved**，写入 `OPEN_QUESTIONS.md`；不得在 `STATUS.md` 写成已证明。
3. **真机 vs 模拟器冲突 → 拆成两条 claim**，各自带 E 级别，不合并、不互相“校正”。例：t0=4 fast path 的 lab 语义（E3）与真机可达性（未证）是两条。
4. **需要新实验才能裁决 → 写最小复现实验**（命令 + 预期输出 + 判据），不猜结论。
5. **重跑优先级**：能静态裁决的先静态（反汇编/源码/文件比对）；必须动态的，写清 lab 命令与预期输出。

## 4. 引用格式

- 单行：`path/to/file.md:123`
- 区间：`path/to/file.md:606-631`
- 同一文档多处：`file.md:12,19,44`
- 允许省略 `./` 前缀；路径相对于 `/home/user/gsp_libos_clean`。
- 归档副本不作为引用源：引用一律指向**原始路径**（原件仍在原位）。归档副本见 `docs/ARCHIVE_INDEX.md`。

## 5. 常见反模式（引用时请勿复制）

| 反模式 | 为什么错 | 正确写法 |
|---|---|---|
| “已硅晶验证” | 未说明是裸机还是直通 VM | `E0` 或 `E1` + 环境 |
| “真内核上验证” | “真内核”= 真机固件 ELF，但可能由模拟器执行 | `E4，镜像 kernel_gb20x_REAL.elf` |
| “A 级发现” | 作者自评，不是证据级别 | `E0，高置信度` |
| “QEMU 已启动成功” | 只是 lab profile 到达某检查点 | `E3，本 profile 到达 0x…；完整链未完成` |
| “签名验证通过” | 可能只是宿主侧包验证 | `E3/宿主侧，不等于芯片熔断/BOOTROM 认证` |
| “永久 DoS” | 未最小化触发序列 | `E0 现象；最小触发未知（OQ-06）` |

## 6. 与项目约定的关系

`AGENTS.md` 要求：不伪造启动进展、未建模的 FSP/CSR/DMA/权限必须显式暴露缺口。本分级是实现该约定的文档层机制：

- 任何 `STATUS.md` 里的“已完成”必须能追到一条 `FINDINGS.md` 的 E0/E1/E2 条目；
- 任何 E3/E4 条目不得出现在“真机结论”区；
- 缺口与未决项一律进 `OPEN_QUESTIONS.md`，不得用“待补充”掩盖。
