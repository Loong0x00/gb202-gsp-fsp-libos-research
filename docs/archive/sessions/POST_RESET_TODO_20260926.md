## 0. 复位说明
- 现状:**MNOC port 1 锁死**(ERR 只读位,`0x8f1f90=0x060fffff`)+ **EMEM 通道不再回包**
- 成因:V1 实验(声明 1 MiB 但只推 9 B)⇒ MNOC 硬件校验声明长度,违规锁存 ERR 打死端口
- 复位:**先试热重启**(便宜,约一半概率);不行则**断电**(已知 FSP 易失状态只有断电才清)
- 复位后先验证:`insmod fsp_od_mod.ko`(对照,声明=实际=9)应能拿到 `err=0` + 20 字节回包;
  失败说明还没清干净 ⇒ 断电

## 1. 第一件事:扫 MNOC 的**合法声明范围**(必须最先做)
顺序(每步 `declared = push`,即声明与实际一致 ⇒ 不触发校验):
```
0x40 0x100 0x400 0x1000 0x4000 0x10000 0x40000
```
模块:`sudo insmod fsp_od_mod.ko declared=N push=N fill=0xaa no_recv=1`
判据:`ERR` 位是否置起 ⇒ **找出硬件允许的最大 MESSAGE_SIZE**
(注意:一旦 ERR 置起,该端口本轮就废了 ⇒ **从小到大**跑,见 ERR 立即停)
意义:这个上限本身就是新知识(端口/FIFO 容量),而且它决定 V2 能用多大。

## 2. 第二件事:协议层不一致(真正没测过的那个变体)
> 关键区别:**声明 = 实际推送量**(硬件校验通过 ✓),让**报文内部的头**撒谎 ✗

- **V2a**:声明=推送=小(如 0x20),但报文里 NVDM 头声称的载荷很大 ⇒ 看 FSP 是否按头长度取
- **V2b**:声明=推送=大(合法上限内,如 0x1000),但头部声称 20 B ⇒ 看接收端按谁分配
- **V2c**:多包组合(SOM=1,EOM=0,SEQ 递增,中途 EOM=1)但总长与头部声明不符
判据:FSP 回 `errorCode != 0` / `ERR` 位 = 安全;WDT / 不可纠正错误 / 信箱挂死 = **有 bug**
风险:可能再次打死端口 ⇒ **每个变体之间插入一次"对照发送"确认端口还活着**
