新发现 (第 33 个 bug): boot 阶段连发 2 条非 boot 消息 → EMEM 队列永久卡死 → 系统整机冻结。FSP 消费消息但不重置队列状态。

## 今日新实验: 手动发 COT (也不回)
- 驱动 boot 时发 COT → FSP 回应 ✓
- Boot 完成后手动发 COT → 无响应
- 原因: FSP 已切换到 runtime 模式, boot dispatcher 不再活跃
- FSP 的行为: 每次 boot 短暂"醒来"处理 COT/FRTS → 切到 runtime → "晕过去"

## HULK 证书攻击蓝图 (等 FSP 复活后执行)

来自 hulk_public_research_20260811/ 的发现:
- parse_hulk_certificate.py 已完整逆向证书格式
- 样例证书的 algorithm word: hash=SHA256, crypto=none, alt_crypto=3AES128
- crypto_id=0 表示"无主签名" — NVIDIA 自己的样例就是 crypto=none!
- 如果 FSP 不拒绝 algorithm=全零 → 任意寄存器 RMW

攻击步骤:
1. 修 FSP (T76 清 flash 死亡标志)
2. 构造 HULK 证书: type=0x0C, algorithm=全零, device_id=0x2B85, ECID=从GPU读, RMW记录(解锁 PLM f8/dc/d0)
3. MNOC p1 发送 NVDM type 0x11
4. 如果通过 → 任意寄存器写 → Fabric 解锁 → 读 FSP IMEM → 明文到手

证书格式 (v2, 148 字节):
```
Header 64B: version=0x20, struct_size=0x2C, device_id=0x2B85,
            cert_type=0x0C, algorithm=0x00000000(全none), flags=0,
            timestamps
DEVICE_ID block 12B: type=0x0B, device_id=0x2B85
ECID block 16B: type=0x0A, ECID=0x203A4E87_E0440100 (从 0x820000/08 读到)
RMW block 48B: type=0x07, 3条记录:
  addr=0x8200F8 and=0 or=0xFFFFFFFF (PLM latch)
  addr=0x8200DC and=0 or=0xFFFFFFFF (PLM L2)
  addr=0x8200D0 and=0 or=0xFFFFFFFF (PLM floorsweep)
```

## 环境恢复步骤 (如果驱动没加载)

```bash
# 内核 headers 可能缺失, 先装
sudo pacman -S linux-headers
# 编译
sudo dkms remove nvidia/610.57.04 --all 2>/dev/null
sudo rm -rf /var/lib/dkms/nvidia
sudo dkms add /usr/src/nvidia-610.57.04
sudo dkms install nvidia/610.57.04 --force
# 加载
zstdcat /lib/modules/$(uname -r)/updates/dkms/nvidia.ko.zst > /tmp/nv.ko
sudo insmod /tmp/nv.ko
```

注意: 内核版本可能变化 (7.2.6 vs 7.0.14 vs 7.2.7), headers 必须匹配。
如果 headers 缓存有旧版: `sudo pacman -U /var/cache/pacman/pkg/linux-headers-<版本>.pkg.tar.zst`
