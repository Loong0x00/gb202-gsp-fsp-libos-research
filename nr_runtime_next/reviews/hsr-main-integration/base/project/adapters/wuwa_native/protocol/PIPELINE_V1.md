# Frozen D5RP v1: independent NR order/stack extension

Scope: native owned host/runtime and existing Linux manager. D5LC v1 remains
exactly 72 bytes, unchanged, for existing NR enable/scalar controls. No ReShade
or RenoDX is needed by this extension. Old backends cannot acknowledge it.

## Request: .dlss5-linux/pipeline-control.bin

Little endian, packed32 bytes. Python `<IHHQIIII`.

|offset|type|field|
|---:|---|---|
|0|u32|magic 0x50523544, bytes `D5RP`|
|4|u16|version1|
|6|u16|size32|
|8|u64|sequence, nonzero; fresh per application|
|16|u32|order: 0 post (SR/RR→NR); 1 pre_sr (NR→ordinary SR only)|
|20|u32|passes1..10 (actual independent NR evaluations, not intensity or FG)|
|24|u32|reserved0|
|28|u32|FNV1a32 of preceding28 bytes|

Atomic same-directory write+rename. Invalid length/version/checksum/sequence/
order/passes/reserved is rejected without applying a partial request. Missing
request defaults to post/1. D5LC enable0 disables all NR regardless of this request.
Order/pass count are cold/process-latched initially; new requested values report
pending_restart, not applied. Never relabel old runtime state as a new request.

## Installed capability: .dlss5-linux/pipeline-capabilities.json

Static, only installed with an actually compatible backend (not generated by the
manager for an old backend):

```json
{"schema":"d5rp-capabilities/v1","backend":"dlss5-native","backend_build":"BUILD_ID","pipeline_protocol":1,"supported_orders":["post","pre_sr"],"max_nr_passes":10,"requires_restart":true,"pre_sr_requires_feature1":true}
```

`post` may be used after successful SR or RR reconstruction; `pre_sr` is never
advertised for a non-SR game adapter. max_nr_passes describes implementation range,
not a guarantee that ten layers fit every resolution/GPU. Exact build is recorded.
Caps are JSON <=16KiB, required fields/type/ranges checked. Unknown optional fields
may be ignored; unknown schema/protocol or inconsistent required fields rejected.

## Actual runtime: .dlss5-linux/pipeline-status.json

Worker-written atomic JSON <=16KiB, heartbeat <=5 seconds old for a live UI result.

```json
{"schema":"d5rp-status/v1","pid":123,"session_id":"unique-start-id","heartbeat_unix_ns":1,"sequence":1,"requested_order":"post","requested_passes":1,"effective_order":"post","effective_passes":1,"state":"active","reconstruction":"sr","reason":""}
```

Required fields as above. Integers cannot be booleans. sequence is the most recently
observed VALID request (not automatically effective). State is one of active,
disabled,pending_restart,unsupported,gate_closed,budget_exceeded,error. Reconstruction
is sr,rr,none,unknown. effective_order is post/pre_sr; effective_passes is0..10
(0 when no NR work is active). Active requires effective values to match requested
values, effective_passes>=1 and successful real NR execution. Pending restart may
report the currently latched effective chain plus the new requested chain. Reason
is bounded descriptive text, not a command. Manager requires fresh heartbeat,
matching sequence AND requested values; a D5LC receipt alone proves nothing about
D5RP. Missing/stale/bad status is unconfirmed, not active. Optional diagnostics may
include actual NR call counts, per-layer handles/creation counts, budget, phase gate.

## Safety/implementation contract

Production runs ONE chosen chain and ONE game SR/RR history, not the experimental
two-SR comparison graph. Each NR layer owns independent handle/history/reset; raw
neural layers ping-pong through bounded surfaces with final HDR composition once.
No shared temporal handle evaluated repeatedly as a substitute for layers. Create
execution acknowledgement and GPU lifetime use native queue/list hooks, not
ReShade event numbers or private unwrapping UUIDs. Disabled/failed/budget-rejected
jobs preserve the game path and do not feed stale images into presentation.

Guardians/loading/phase gates override requests. RR+pre_sr returns unsupported with
NR bypass; never silently moves NR to post or changes RR/game settings. Unsupported
adapter paths remain unavailable in the manager. Do not advertise/test-success
for stub or configuration-only backends. High-layer VRAM estimates/guards are
mandatory; OOM is not an acceptable capability probe. Signed NVIDIA files,
hardware settings and unrelated games are not changed.
