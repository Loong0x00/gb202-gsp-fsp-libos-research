# Legacy test proof-file writes — Main disclosure and confinement

The original4h oracle worker disclosed that invoking the existing reference test CLI rewrites sibling `COVERAGE.json` with identical bytes. Main checked its own direct reference-test invocations and found the same pattern in five reviewed test suites:4h,4hDS,8h,8hDS write `COVERAGE.json`; split16 entry writes `EDGE_PROOF.json`.

These successful tests executed those writes. All five files still match their previously accepted published hashes (`CHECK.json`), but identical content does not prove no write or timestamp preservation. No unknown timestamps were restored or fabricated. This is confined to research proof artifacts, not installed games, source PTX, weights, configurations or GPU execution. Main's earlier blanket wording that no worker artifacts were overwritten was too broad and is corrected by this note.

`guarded_tests.py` now redirects only each explicitly named proof-file write into this Main directory, requires its regenerated bytes equal the frozen original, and uses a Python audit hook to reject other out-of-output filesystem writes/mutations during these reviewed Python tests. It is a test containment measure, not an OS security sandbox for arbitrary native code.

Main reran DS8's16 tests and split16's9 tests with this wrapper. Both pass; original proof bytes AND mtime/ctime remain unchanged across the guarded runs. Local generated proof files and per-case `RESULT.json` record this. The earlier4h,4hDS and8h test outcomes remain valid content checks, but are not retrospectively labeled write-free. Future invocations should use the wrapper rather than the legacy test CLIs.
