## Critical risks / launch gates

1. **Confirmed authorization blocker for direct reuse: experimental zero reserve.** `native/common/control.h:157-160` explicitly labels temporary Quality POST5 and sets `e.reserve=0`; `native/host/wuwa_budget_policy.h:116-119` permits zero; `native/tests/policy_test.cpp:98` asserts zero. Normal reserve restoration must include the admission predicate/test expectations, not just a label/config change. Both host live budget (`wuwa_ingress.cpp:533-543`) and runtime creation budget (`runtime/pipeline.cpp:179-186`) consume the shared estimate. The normal numeric formula is not present in this frozen source, so it is not inferred here.
2. **Confirmed unguarded compute-state dependency.** FormatBridge binds descriptor heaps, compute root signature, PSO and root parameters (`bridge.cpp:588-605`) without restoring prior compute state. `ParameterGuard` is only NGX Color/X/Y, NOT a D3D12 root-state guard. Host explicitly relies on the next full signed SR Evaluate to establish its own root/PSO/heaps (`pipeline.cpp:335-336`). This also matters when PRE normalization records but later NR admission/create/commit fails and the host falls back to signed SR. CPU checks cannot prove the signed implementation actually rebinds everything; prior POST5 success does not prove this new PRE seam.
3. **Confirmed restoration-failure hole in fallback safety, not in active-status gating.** If temporary bind fails AND `guard.restore()` is unverified, `pipeline.cpp:325-333` nevertheless calls original SR with the same parameter map. If bind succeeded but restore fails after original (`337-342`), it returns original success while marking host commit failed, potentially leaving the parameter map altered for later calls. There is no destructor/RAII retry/exception cleanup in `170-199`. Thus “one original” is proven; “all failure fallbacks use untouched original parameters” is NOT. Existing CPU tests exercise a pure happy-path fake Color map, not the actual NGX vtable or failed X/Y restore (`native/tests/policy_test.cpp:85-87`). Treat any bind/restore error as a stop condition, not a reason to accept continued PRE.
4. **Strict live format/state assumptions:** PRE only accepts source RGBA16F, WuWa float2 MV and float depth (`format_plan.cpp:175-179,205-209`). Host states are explicitly attested declarations, “never queried” (`wuwa_ingress.cpp:900-908`), not observed resource-barrier tracking. Wrong formats reject; wrong *actual* resource states are not disproved by GetDesc or this CPU audit. The PRE replacement's SRV state is trusted from runtime, not introspected by FormatBridge.
5. **NR OFF is not necessarily zero adapter GPU work:** while unattached, `wuwa_ingress.cpp:830-834` can run the budget-guarded compatibility probe (`693-714`) including normalization; runtime probe is disabled. This does not perform Feature18 evaluations or make PRE accepted. Startup lease also explicitly does not claim continuing world/loading-screen detection (`294-306`).

## GPU ordering and retirement audit (source proof, not execution proof)

- Runtime tracks evaluation before any copy/interop (`native/runtime/pipeline.cpp:480-486`); copies current normalized resources, uses Begin/EndVkCommandBufferInterop and pre/inter-layer/post barriers (`487-559`). PRE replacement remains runtime-chain-owned; FormatBridge does not independently own/AddRef it. Its lifetime therefore depends on runtime chain tracking through the same command list including the subsequent signed SR.
- Queue hook calls original ExecuteCommandLists **first**, matches exact recorded lists/device identities, then signals the same queue (`native/host/queue_hooks.cpp:216-305`). Format-only paths get a tail fence even if NR was disabled/pending/rejected. Both runtime and format callbacks receive that post-forward fence. No host render-thread GPU wait was found in these paths.
- Bridge accepts submitted fence only for a valid direct queue/device (`bridge.cpp:991-1008`), reuses/releases external refs only after GetCompletedValue reaches the fence, rejecting UINT64_MAX device-removal as completion (`702-718`). Successful Reset is forwarded before invalidation (`queue_hooks.cpp:172-180`); unsubmitted format abandonment restores prior tracked states (`bridge.cpp:1017-1031`). Signal/device rejection retains resources rather than releasing potentially live work (`wuwa_ingress.cpp:1042-1056`): safe retention can exhaust finite pools; it is not recovery.
- Runtime acknowledges create only after submission and refuses evaluation before acknowledgement (`runtime/pipeline.cpp:740-746,781-786`). Cross-queue use is rejected during post-forward acknowledgement (`764-771`), **not** synchronized proactively. Its shared per-owner textures assume the intended serial/same-queue usage. Retirement waits for no pending records plus completed last fence, and retains lifetime-unproven chains (`617-648`).
- CPU commit and queue Signal are not GPU acceptance: host waits for current-epoch sampled completion before active (`native/host/pipeline.cpp:650-657,700-707`); runtime worker excludes device removal and failed/retiring chains (`runtime/pipeline.cpp:620-635`). Live PRE3 requires positive current-epoch three-layer/effective-pass evidence and signed-SR/restore/commit plus GPU-completion evidence, not an EVALUATED return alone.
