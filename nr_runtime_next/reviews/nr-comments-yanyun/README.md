# 燕云十六声 DLSS5 / NR：视频简介与真实公共评论核查

## 最重要的发现

**拿到了真实评论，且找到了UP亲自给出的参数与原图，不只是搜索标题。** 本次仅研究6个目标视频：4条指定线索 + 1条燕云教程 + 1条鸣潮跨游戏对照。没有“必须来自同一来源”的限制，也没有为了相似感受去认定它们使用同一套参数。

1. **最有用的是 Kodakchrome 的置顶帖。** 其原图明确显示：`NR Preset=Default`、`NR Style=Natural`、`NR Intensity=2.00`、`Local Tone Strength=2.00`、`Local Structure Strength=2.00`、`Skin Structure Strength=0.60`。另一个图勾选的是 **ReShade `HDR [FakeHDR.fx]`**，参数 **Power 0.705 / Radius 1 0.711 / Radius 2 0.688**。这不是“RTX HDR已开启”的证据，也不是“两层NR”的证据。
2. **“最舒服调色”那条温煦视频，没有公开简介配方，取到的评论中也没有UP配方。** 观众确实自报“两倍叠层”，但那是观众自己的附图，不应替换成温煦UP的做法。
3. **“为什么燕云尤其像实拍”的公共讨论，集中于地编/美术/场景已有基础，光影与材质观感得到补强；这些都是观众解释，不是技术实测。** 另有评论在明确声称“没开DLSS5”的图片下同样说分不清现实——单靠“像真的”不能识别处理链。
4. **复现并不一致。** Kodak参数楼有人说“我这么调了也没有视频的效果”；Natural被嫌锐化；教程楼有初始化失败、帧生成不起作用和极低帧率报告。不能承诺照抄就达到视频效果。
5. **渲染顺序与帧率有很具体的UP表述，但不可张冠李戴。** 鸣潮UP称把NR移到超分之前，并称“质量模式 + 2倍帧生成 + 2倍Lossless Scaling”达到120帧。这不是燕云的验证，也不是“原生6K120”。

原文、rpid、作者mid、是否UP、时间、父楼、原始JSON位置见 **[evidence.md](evidence.md)**；六条完整简介见 **[descriptions.md](descriptions.md)**。时间均为2026年、UTC+8，由接口时间戳转换，不仅按“8/29”等显示标签猜年份。

## B. “为什么燕云像实拍/通透，而某些游戏不一样？”能说到哪里

- **E04/E05（火力全开评论）**：永生花和月亮与瑾轩羽分别认为燕云“美术地编和环境”很好、光影/材质是短板，因此变化显著。可总结为**评论区对美术基础+光影观感的解释**；不能升级成已证明的物理照明重建、训练域匹配或透光材质生成机制。
- **E26（怪蜀黍楼内）**：有人比较燕云与二游后，努力变棕熊的考拉 / mid 520564796 于09-06 14:06:16回复“美术风格不一样啊”，rpid **313112856913**。这是风格差异意见，不是底层算法证据。
- **鸣潮完整简介**：玄方研究院称Cinematic“主要角色没那么黑”，场景更自然、材质/衣纹和皮肤表面光影更强，但偶有噪点。与Kodak的Natural构成**不同游戏/不同作者的风格选择对照**，不是同机器受控A/B。
- **E25（鸣潮）**：Kassiny_认为写实化偏离动漫风格。这说明“更写实”与“更合适/更好看”不是同一命题。
- **必要反例 E09/E10**：_LDP___ / mid 92954159 于09-03 14:08:16发“没有dlss5”的图，说明图1手机拍屏；紫色燎原 / mid 697720817 于15:00:05回复“图二都分不清现实还是游戏了”。未实证其拍摄条件，但这条上下文至少阻止把“分不清现实”当作NR专属指纹。

**“通透/半透明”没有被这批证据定义成某个可测的渲染属性。** 更不能凭上述赞叹推定SSS、透射计算、扩散模型、固定三层阈值或具体滤镜算法。本文没有作这些断言。

## C. 教程、渲染入口与帧生成：不要混成一个开关

### 1) 无名的光呆：ReShade Add-on路径

E06/E07 的UP置顶/回复给出：`Reshade 6.8.0_Addon`、`ReShade.ini` 的 `NoEffectCache=1`、历史目录 `yysls_medium\Engine\Binaries\Win64r\`、按 **Insert** 打开此作者包的ReShade菜单，在 **addon** 栏设置DLSS5。作者还明确说用久了会卡顿、需重启。

这是**当时作者提供的包和按键**，不是所有ReShade/OptiScaler版本的统一快捷键。E08观众报设置后依然不生效，日志含 `Failed to find NVSDK_NGX_D3D12_EvaluateFeature_C`。因此不能转述成“改一个ini保证解决”。

### 2) 烟予桐谷：ReShade patch 与 OptiScaler 两种分支

E17 的完整置顶保存在原文索引：作者把50系的patch/ReShade方案，与多帧生成闪屏或20/30/40系的OptiScaler方案区别开；写了 **Home → addon**、取消 **dlss nr** 勾选而保留 **loader** 等步骤。这里不能把“取消ReShade里的NR”说成“整个OptiScaler处理链不开NR”，也不能把“2倍帧生成”说成“2次NR”。

后续勘误很重要：

- **E18**：UP澄清“loader.addon64是个文件”，不是早期置顶写的文件夹。
- **E19**：UP说游戏更新后启动器目录变成 `win64rh`，早期 `win64r` 安装位置可能因此不再匹配启动程序。
- **E21/E22**：2070观众自报只有9帧，插帧开关不生效；UP最后承认“不太清楚”。不存在已证实的通用成功方案。
- **E20**：4060观众提到降画质、使用“nr转sr版本”，是相关个人尝试反馈；没有可审核的帧时间或质量结果。

完整简介确实指向 `https://github.com/Dagherbou/OptiScaler_DLSSNR`。本次只读取公开README，不取二进制、不运行。README说明OptiScaler截获游戏超分调用并转到所选后端，且FG输入/输出另分；**这只能佐证工具类别，不能证明视频具体NR执行位置或当时build**。它还明确警告不要在网游使用，以免触发反作弊封禁。本文是取证，不建议据网盘教程给网游注入文件。

### 3) 鸣潮跨来源：明确的“NR先于SR”作者转述

E23，玄方研究院 / mid 3707016587512597，09-02 13:14:50，rpid **312682909937**：

> 目前已有UP主研究出将DLSS5神经渲染环节移至超分辨率之前，这样可在较低分辨率下进行渲染再超分，损失极小的DLSS5效果，但换来了较大的性能提升。

同帖随后称质量模式 + **两倍帧生成叠加2倍Lossless Scaling**可“完美120帧”，此前为平衡+3倍帧生成。**这是本UP转述另一UP的技术方法，加上自己的运行效果声明**；所引BV只作为文本传送门保存，未新增第7个研究视频。没有GPU/游戏运行、着色器抓帧、调用追踪来确认顺序、实际输入分辨率或无损程度。

## E. HDR / RTX HDR / Freestyle / ReShade 分清

- **Kodak已实证的界面项是 ReShade `FakeHDR.fx`。** 作者写“HDR”，不能据这个字就标注RTX HDR、NVIDIA Freestyle、Windows HDR或游戏原生HDR。
- 本次没有这六条视频使用RTX HDR或Freestyle的直接证据，也没有排除它们在截图之外存在的证据；因此只列“未建立”。
- 没有取得视频媒体流/编码元数据或显示设置，不知道PQ/HLG/scRGB、BT.2020、峰值亮度、SDR映射、录制/上传/播放是否改变色彩。**不能把公共PNG或视频标题视为HDR传递链验证。**
- 截图证明“有哪些参数被展示”，不证明运行中NR与游戏调色、ReShade效果、超分、UI合成及采集之间的严格先后次序；本次只在鸣潮评论取得“NR移到SR之前”的作者说法。
