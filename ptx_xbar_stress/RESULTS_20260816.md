## Workloads

`ptx_xbar_stress` uses inline PTX and covers all 170 SMs:

1. `compute`: register-only integer MAD chains with CPU-side closed-form result
   verification.
2. `l2`: random `ld.global.cg` reads from a 32 MiB L2-resident data set; every
   load is checked against a deterministic per-address pattern.
3. `vram`: transform and verify a 1 GiB data set using `ld.global.cg` and
   `st.global.wb`; the working set is much larger than L2.
4. `atomic`: contended PTX `atom.global.add.u64` operations with an exact final
   operation-count check.

Each run records direct RM XBAR/SYS hardware clocks, NVML clocks/power/load,
dynamic rail targets, kernel events, data errors, and SM coverage.

## Results

### Confirmed 2.9 GHz baseline

Control: GPC request 2900 MHz, NVVDD max 950 mV, MSVDD max 1150 mV
(both dynamic, not fixed), propagation ratio 1.000, XBAR offset +260 MHz.

All four 5-second workloads passed with zero data errors and zero kernel
alerts. Observed average XBAR was 2902.1 MHz (`compute`), 2899.3 MHz (`l2`),
2900.9 MHz (`atomic`), and 2895.7 MHz (`vram`).

### Ratio-only sweep

Keeping the same source request and offset:

| Ratio | L2 XBAR min/avg/max MHz | MSVDD target avg/max mV | Result |
|---:|---:|---:|---:|
| 1.015 | 2919.6 / 2934.6 / 2945.3 | 1138.6 / 1145 | pass, 0 errors |
| 1.030 | 2922.8 / 2942.8 / 2964.7 | 1147.0 / 1150 | pass, 0 errors |
| 1.045 | 2925.6 / 2941.8 / 2971.4 | 1147.3 / 1150 | pass, 0 errors |

Increasing the ratio beyond 1.030 stopped increasing sustained L2 XBAR. The
controller reached the 1150 mV MSVDD ceiling and reduced the source bin.

### OCN-like topology check

Control: GPC request 3000 MHz, NVVDD max 980 mV, MSVDD max 1065 mV,
stock 0.899902 propagation, XBAR offset +300 MHz.

This did **not** produce a 3 GHz physical XBAR on this Linux path. The compute
run averaged 2699.1 MHz XBAR. Therefore the OCN result cannot be reproduced by
assuming `3000 * 0.9 + 300` as a direct physical-frequency equation.

### Physical 3 GHz boundary

The ratio was set to 1.000 while keeping GPC request 3000 MHz, dynamic NVVDD
max 980 mV, and dynamic MSVDD max 1065 mV. XBAR offset was then swept.

| XBAR offset | Workload | XBAR min/avg/max MHz | Result |
|---:|---|---:|---|
| +330 | compute, 1 s | 2894.9 / 2900.6 / 2910.4 | pass, 0 errors |
| +360 | compute, 1 s | 2919.3 / 2931.1 / 2937.5 | pass, 0 errors |
| +390 | compute, 1 s | 2955.1 / 2961.4 / 2969.3 | pass, 0 errors |
| +420 | compute, 1 s | 2981.9 / 2992.1 / 3004.0 | pass, 0 errors |
| +430 | L2, 5 s | 2959.9 / 2974.2 / 2999.5 | pass, 0 errors |
| +430 | VRAM, 5 s | 2961.7 / 2972.8 / 2991.4 | pass, 0 errors |
| +440 | compute, 2 s | 2988.1 / 3000.1 / 3010.5 | pass, 0 errors |
| +440 | atomic, 3 s | 2986.3 / 2997.7 / 3006.0 | pass, 0 errors |
| +440 | L2, 3 s | 2965.8 / 2988.6 / 3004.6 | **fail: 1 data error** |

The failing +440 L2 run performed 423,540,817,920 checked loads and observed
one incorrect value. CUDA remained operational and the kernel logged no Xid,
AER, GSP health event, or PCIe error. This is a silent data-integrity failure,
not a display or GSP crash.

The immediate +430 A/B control completed 985 rounds (about 2616 GiB of checked
L2 traffic) with zero errors, followed by about 6723 GiB of checked VRAM
traffic with zero errors.

## Conclusion

- A physical XBAR average of approximately 2900 MHz is confirmed across all
  four workload classes.
- A physical 3000 MHz XBAR can execute compute and contended atomic workloads
  briefly at dynamic NVVDD <= 980 mV and MSVDD <= 1065 mV.
- It is not data-stable under the tested L2 traffic: the first sustained run
  whose samples crossed 3 GHz produced a silent read error.
- The best tested no-error boundary is the +430 configuration, but its
  sustained L2/VRAM averages were 2974/2973 MHz and did not remain above 3 GHz.
- No SBR or reboot was required. Experimental controls were restored, GDM,
  LACT, and `nvidia-persistenced` were restarted, and the full sweep contained
  zero kernel alerts.

## Follow-up

`RESULTS_MIXED_20260816.md` adds true mixed compute/L2/VRAM/atomic kernels and
an isolated-L2 reproduction run. The original single +440 L2 mismatch did not
reproduce in 1.41 trillion later isolated-L2 loads or 3.23 trillion checked
loads across the expanded +440 matrix. Treat the original event as a confirmed
observation but not yet as proof of deterministic +440 instability.
