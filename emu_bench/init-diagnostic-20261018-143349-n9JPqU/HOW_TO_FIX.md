# 正确修复路线与新增基础语义证据

## 先修正诊断优先级

进一步检查发现，自写 Python 模拟器存在标准 RV64 指令语义错误。因此之前复现的零节点循环是**该实现和当前输入下的真实观测**，但还不能排除是指令执行错误造成，更不能直接认定其唯一根因是缺少 BootROM 内存。

对同一条指令做单步微测试，并用 QEMU RV64 对照，得到：

| 项目 | Python 当前结果 | 正确结果 / QEMU 对照 |
|---|---|---|
| `lui t0,0x93000` | 0x0000000093000000 | 0xffffffff93000000 |
| `sext.w t0,t1`, t1=0xffffffff00000000 | 0xffffffff00000000 | 0 |
| `addw`, 0x7fffffff+1 | 0x0000000080000000 | 0xffffffff80000000 |
| `csrs sstatus,t0`, 旧低位=0x20，t0=2 | 0x2，覆盖旧位 | 低位 0x22，保留旧位；QEMU 另保留只读 UXL 字段 |
| `div`, -7/3 | -3 | -2，向零取整 |

证据：`10_isa_semantics_probe.log`、`11_qemu_isa_reference.gdb.log` 与 `11_qemu_isa_reference.qemu.log`。

源码位置：`rv64_emu.py:73–75` 的符号扩展未先限制源位宽；`318–328` 的 LUI 没有按 RV64 将 32 位结果符号扩展；`304–316` 的 W 结果没有统一符号扩展；`377–378` 将 csrs 当成赋值而非按位 OR；`299–312` 使用 Python 除法/取余规则，与 RISC-V 有符号规则不符。

这意味着旧记录中的“boot 自动进入低别名”至少可能混入 LUI 模拟错误。不能把它直接作为真实硬件的地址空间事实。

## 推荐主线：QEMU 的标准 RV64 + 单独的 GSP 平台模型

不要修改原始 LibOS 指令；不要让自写解释器未经验证就承担事实基准。

1. **执行语义基线**
   - QEMU 负责标准 RV64I/M/C 等指令。
   - 若保留 Python 模拟器，先给符号扩展、32 位运算、压缩 load、CSR 位操作、除法、异常返回等建立与 QEMU 对照的测试，再修实现。
   - 在这些测试通过前，不能依靠 Python boot 结果推断缺了哪些硬件。

2. **恢复原始 boot，而不是直接跳 init**
   - 固定 REAL ELF 哈希、原始程序段和装载布局。
   - 启动器仅提供已证实的 BootROM 入口契约；让内核自己的启动代码建栈并进入 init。
   - 通过入口寄存器使用点、公开启动描述符、可用的上游 bootloader 代码恢复 ABI。不能凭“某比较要求 3”就声称 a5=3 是完整正确参数。

3. **实现 GSP 自定义 CSR 和地址空间行为**
   - 在独立 QEMU 开发构建中增加相应 CPU 扩展/翻译逻辑，不覆盖系统 QEMU。
   - 对 0x5ca–0x5cf 等按索引保存窗口配置，建模提交、更新、禁用、权限和地址变换的副作用；不能只是记录数值或无限追加别名。
   - 每次取指/读写应用正确映射和权限；不满足时产生正确异常，让原始固件处理。
   - 寄存器字段目前仅部分逆向，必须标注已证实/待证实；不能把现有 Python 模型当作完整规范。

4. **BootROM 服务按实际 ABI 和内存副作用实现**
   - 对首次遇到的 ecall，记录全部参数、调用点、调用前后预期数据结构。
   - 从调用者的结果使用方式、真实服务代码/公开资料确定服务号、返回码、输出寄存器和写内存行为。
   - 不支持的服务明确停机报告；不统一返回 0，也不直接假设等于标准 Linux/OpenSBI 接口。

5. **在正确执行基线上再追零节点来源**
   - 对链表头和 next/prev 的写入设置观测，定位第一次初始化以及第一次破坏。
   - 判断是 init 本应执行的路径没执行、地址窗口写入了不同物理位置、还是确有外部启动输入缺失。
   - 修负责建立状态的生产者，不把空指针改成某个能继续跑的值。

6. **只补当前真实遇到的外设**
   - MMIO 返回值、定时器、门铃等依据现有代码的协议逐项实现。
   - 未实现地址默认报告访问错误，而不是全零 RAM。
   - 若需要现实硬件观测，应单独确定安全范围和授权，不能把已有 VFIO VM 当作可随意修改的验证台。

## 验收标准

- 原始内核哈希不变，无 NOP/强制分支/直接跳过初始化。
- 标准指令边界测试与 QEMU 一致。
- 所有成功的 BootROM 调用都有明确的服务语义，而非假成功。
- 能从 boot 入口自然走到 init，关键链表/池不变量成立。
- 进入调度器或真实任务入口，并能说明该到达点的证据；“多跑了几百万步”不是成功标准。

本轮新增的是定位证据和修复设计，**尚未修改原始模拟器、引导或固件**。
